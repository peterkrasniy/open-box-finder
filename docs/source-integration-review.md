# Source integration review boundary

This is inactive implementation prepared after the research gate. It does not admit a source, establish public inventory, or prove an unattended job. Parent retains source/security acceptance and independent audit ownership.

`app/api/catalog/route.ts` exposes GET/HEAD. `lib/server/catalog-route.ts` rejects every query string and write method before invoking maintenance; HEAD reads without maintenance. No visitor-supplied URL, records, price, adapter, force parameter, SQL, authorization, cookie or location enters acquisition. The server chooses immutable transport definitions, a recognizable project User-Agent, manual redirects, omitted credentials, strict content types, bounded bytes and eight-second requests.

`lib/server/catalog-store.ts` uses a shared D1 lease, minimum fifteen-minute global cadence and ninety-six attempts per UTC day. Publication must match the active unexpired lease and exactly increment the stored sequence. A disabled/revoked source is rejected both when writing and when reading existing stored payloads. SQL values are bound; database/schema identifiers come only from source. Operational counts contain no shopper profiles or raw retailer error bodies.

`lib/server/pipeline.ts` selects one due, admitted adapter per maintenance cycle. An incomplete response preserves missing prior records; an unconfirmed empty response is a failure. Invalid origins, comparisons and malformed acquisitions preserve the previous records and publish error health. Failure never freshens item observation timestamps. Successful complete observations alone advance removal evidence. `lastSnapshotComplete` exposes partial checks; the visible source summary includes checked/attention/disconnected counts. DealNews remains separate complete original editorial content with original links/referral codes, not normalized price or stock.

The configured production source registry remains entirely disabled. `APPROVED_POLICIES` and `APPROVED_PREFLIGHTS` are empty. A database binding and schema can be published without creating retailer records or acquisition attempts. All synthetic offers and injected test grants are confined to tests.

The proposed optional preflight in `lib/server/preflight.ts` uses only two fixed candidates. DealNews performs one licensed RSS read and retains only counts/link origins. Sacramento performs robots + catalog + at most two reviewed exact unit-page reads. A denial, redirect, malformed/unsupported policy, positive crawl-delay, unsafe path or unsupported item representation stops that candidate. Robots compliance is not access/redistribution authorization; this distinction follows [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html). The conservative checker declines unsupported cases. Unit preflight uses exact item-level structured stock/USD cents evidence; a generic Add to Cart, model category, aggregate price or repeated first-page result is insufficient. Every preflight catalog remains explicitly incomplete.

Preflight evidence is private, bounded to 16 KiB per source, and protected by the same lease when stored in `source_preflight`. It contains no full HTML/feed bodies, media, customer data or credentials. It is excluded from public catalog responses and permanent Git catalog history. A twenty-four-hour expiry and hourly cadence are specified; physical cleanup depends on actual maintenance execution and must be verified before claiming retention enforcement. Runtime transport and actual unit availability remain unverified in this executor because its configured proxy denies both retailer endpoints and the published app before origin.

The research refresh contract requires parent confirmation of this concrete maintenance boundary before enabling it. Keep both approval maps empty until the parent security/source owners accept it and actual permitted hosted responses are reviewed. No new retailer credential, enrollment, paid service, anonymous production workaround or authorization grant is part of this batch.

Required remaining evidence: independently permitted public HTTP/browser checks; accepted hosted transport/terms/media and actual units; durable real acquisition/write/readback; a Sites-native scheduled run that actually executes; a real added/changed/removed source trace adopted by an already-open browser; native iPhone/VoiceOver and final independent candidate reviews. A successful Sites deploy, directory, empty catalog or synthetic generation test is not first complete.
