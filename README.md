# Open Box Finder

A responsive English/Russian app for open-box deal discovery, local pickup, shipping, and device-local saves. Canonical source: https://github.com/peterkrasniy/open-box-finder.

**Current milestone:** four individually reviewed Sennheiser refurbished products appear as factual product cards with observed page prices, conditions, direct retailer links and device-local saves. These are manual observations with a 24-hour review window, not verified live inventory. All automated retailer adapters remain disabled. The Site at https://open-box-finder.peter-krasniy.chatgpt.site is owner-private; the canonical GitHub source remains public. Automatic permitted acquisition and fresh stock remain pending.

## Run and edit

Use Node 24 (minimum 22.13) and npm. A fresh canonical GitHub clone at the version-4 commit was installed, tested, typechecked, linted and built in an isolated clean checkout in this environment; framework-generated build IDs can differ. Install the committed dependency state with `npm ci`, then run `npm run dev`. The app's own UI lives in `components/`, client hooks in `hooks/`, offer/filter/price/persistence rules in `lib/`, and protected acquisition modules in `lib/server/`. English/Russian strings are in `lib/i18n.ts`; responsive styles are in `app/globals.css`. The original app-icon source is in `assets/`; only the derived install icons ship from `public/icons/`.

Run `npm test`, `npm run typecheck`, `npm run lint`, and `npm run build` before sharing changes. `npm run db:generate` creates the D1 migrations after schema edits. Runtime data is not seeded in source. Synthetic records are confined to tests and isolated browser fixtures.

## Sources and freshness

A source is admitted only after permitted acquisition, actual item availability, stable exact identity, price/reference semantics, freshness, and media rights are checked. `lib/sources.ts` contains the current admission state; `docs/research/source-feasibility.md` records the broader retailer review. Directory links, cached research observations, syndication, and verified unit inventory are distinct.

The source transport uses fixed developer-defined HTTPS endpoints, bounded responses, no redirects, timeouts and server backoff. The inactive durable writer uses a D1 database lease, daily quota, strict next-sequence publication and source admission gates. Schema-only local migrations and compiled Worker reads are tested. Hosted source acquisition and unattended execution are not verified; the publication map remains empty. The accepted timestamped private A4L preflight was consumed during a canceled hosted invocation, with no persisted observation. Its marker prevents replay. A local lifecycle fix retains the same bounded maintenance promise with the trusted Worker waitUntil hook; it neither renews the grant nor admits inventory. Public visitors cannot submit records or set ingestion URLs. Shopper preferences and saved identity/link pointers stay in this browser; prices and offer payloads are not stored in localStorage.

Comparisons appear only with a fresh supported reference for the exact variant, labeled as current-new/MSRP/retailer-list/regular/previous price. Unverified comparisons do not produce a savings percentage. Local delivery does not imply national shipping. Pickup directions target the verified exact branch.

## Interim outbound navigation

The app provides human-reviewed links to Best Buy Outlet, its open-box category pages and outlet locations, plus a short-lived community discussion link. These are navigation bookmarks outside the catalog and filters; they establish no stock, current price or savings. The app makes no requests to those destinations until a visitor clicks. No provider titles, offer descriptions, images or logos are imported. Dated community leads automatically hide after their manual review window; evergreen category links remain available. Edit `lib/outbound-links.ts` and the original UI labels to maintain this section; review destination state and provider restrictions before adding any lead. ## Individual product curation

`lib/manual-products.ts` contains four original model labels and manually reviewed US Sennheiser product-page facts. Each card names its condition, observation time and unknown availability/fulfillment. Retailer, audio category, query and observed-price filters apply. Pickup-only and shipped-only filters exclude these records because neither mode is verified. Savings sorts do not fabricate exact-variant savings rankings. New-model comparison rows link to the same retailer’s corresponding new-condition model page; they are observations, not former refurbished prices. The observed retailer comparison amounts are red and struck through, explicitly labeled “Retailer comparison price” with their basis unspecified. Separately observed new-model prices remain plain; equal pricing is clearly labeled. Ambiguous retailer references never drive savings ranking. No product marketing descriptions, images, logos or retailer inventory payloads are copied. Cards link to exact product pages and the app does not fetch those pages.

A trusted catalog server clock hides these cards after the 24-hour review window. Saved entries retain only identity, model label and product link; they show an expired-review message without the old price after expiry. To refresh the small curated set, manually review the exact product pages and relevant terms, update factual notes and review timestamps, then test and publish the exact source commit. This is deliberate manual maintenance, not an automatic inventory adapter. Sennheiser's reviewed consumer-sales terms revealed no specific manual factual-reuse restriction; this is not a media or bulk-feed license. Source-specific restrictions and access failures still apply to other retailers.

The manifest link uses `crossorigin="use-credentials"` so private Sites sessions accompany manifest requests. Platform access controls remain unchanged. Signed-in Chrome validation of the deployed manifest and logged-out protection remain separate browser checks.
